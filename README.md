## 为什么网站和小程序需要快递查询 API？

电商订单、售后工单和客服咨询都离不开物流状态。用户想知道包裹是否发出、当前到达哪里、什么时候签收，如果每个项目都单独对接多家快递公司，不仅开发工作量大，返回字段和状态编码也难以统一。

快递查询 API 可以把“输入快递单号、识别承运公司、获取物流节点”封装成一次标准 HTTP 请求。网站、商城、小程序和客服系统只需要传入单号，就能在自己的页面中展示快递公司、当前状态、最新节点和完整物流轨迹。

## Tmini 快递物流查询接口有什么功能？

Tmini 的快递物流查询接口接收一个完整快递单号，返回包裹的实时物流信息，主要包括：

- 自动识别快递公司编码和名称，例如 `DBKD`、德邦快递；
- 返回当前物流状态和最新操作节点；
- 返回按时间倒序排列的详细物流轨迹；
- 提供物流状态统计汇总；
- 在有自提柜数据时，返回取件码、存放地址和经纬度坐标等附加信息；
- 使用统一 JSON 格式，方便接入订单详情页、物流查询页和客服后台。

接口适合电商订单物流展示、售后系统、聚合查件工具、企业客服系统和个人开发者项目使用。

## 接口地址、参数和积分规则

| 项目 | 说明 |
| --- | --- |
| 接口名称 | 快递物流查询 |
| 请求方式 | GET |
| 接口地址 | `https://api.tmini.net/apis/autonumber` |
| 鉴权方式 | Query 参数 `key` |
| 必填参数 | `key`、`trackingNo` |
| 当前计费 | 4 积分 / 次 |
| QPM | 不限制（以平台最新规则为准） |
| 接口文档 | [https://api.tmini.net/detail/2](https://api.tmini.net/detail/2) |

这是一个需要积分的收费接口。使用前请先注册 Tmini 账号，在控制台创建 API Key，并准备足够的积分。每次调用都可能产生用量，建议对同一单号设置合理缓存，避免短时间重复查询。

## 请求参数说明

| 参数名 | 类型 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `key` | string | 是 | 控制台生成的接口调用密钥 | `你的密钥` |
| `trackingNo` | string | 是 | 完整快递单号，单次查询一个单号 | `12345678` |

`trackingNo` 应传入完整的数字或字母数字组合，不要带空格、横线或其它分隔符，也不要把订单号当成快递单号。正式项目中建议在发起请求前先做格式校验。

## cURL 调用示例

```bash
curl -G "https://api.tmini.net/apis/autonumber" \
  --data-urlencode "key=你的密钥" \
  --data-urlencode "trackingNo=12345678"
```

也可以直接拼接 Query 参数：

```bash
curl "https://api.tmini.net/apis/autonumber?key=你的密钥&trackingNo=12345678"
```

文章中的密钥仅为占位符，请替换成你在 Tmini 后台创建的 Key。

## Python 快递查询示例

```python
import requests

url = "https://api.tmini.net/apis/autonumber"
params = {
    "key": "你的密钥",
    "trackingNo": "12345678",
}

response = requests.get(url, params=params, timeout=10)
data = response.json()

if data.get("code") != "0000000000":
    print("查询失败：", data.get("msg") or data.get("desc"))
else:
    for package in data.get("data", {}).get("packageInfoList", []):
        print("快递公司：", package.get("cpName"))
        print("当前状态：", package.get("state"))
        print("最新节点：", package.get("operateMessage"))

        for item in package.get("trackingDetails", []):
            print(item.get("time"), item.get("context"))
```

程序应先判断 `code`，再读取 `data`。成功响应中的业务码为字符串 `0000000000`；失败时不要直接访问 `packageInfoList`，应先记录错误信息并执行降级或稍后重试。

## 常用返回字段怎么理解？

### `cp` 和 `cpName`

`cp` 是快递公司编码，`cpName` 是快递公司名称。业务展示时优先使用 `cpName`，如果需要建立自己的快递公司映射表，可以保存 `cp` 作为稳定标识。

### `state` 和 `operateMessage`

`state` 表示当前物流状态，例如 `TRANSPORT` 代表运输中；`operateMessage` 是最新节点的原始描述。状态编码应以接口实际返回为准，不建议只凭猜测写死全部状态。

### `operateTime` 和 `trackingDetails`

`operateTime` 是最新节点时间，格式为 `yyyyMMddHHmmss`。完整轨迹放在 `trackingDetails` 中，每项通常包含 `time`、`context` 和节点状态。接口默认按时间倒序返回，最新记录在前。

### `stateStatList`

这是物流状态统计汇总。例如 `TRANSPORT` 的 `total` 为 `1`，表示当前结果中有一个包裹处于运输状态。聚合订单场景可以用它快速生成状态统计。

### 自提柜相关字段

当包裹进入自提柜或代收点时，接口可能返回 `getcode`、`address`、`onboxTime` 和 `cabinetLocation`。经纬度是否存在取决于物流数据，坐标系由 `locationSystem` 指定，示例为 `GCJ02`。

## 适合哪些应用场景？

### 电商订单详情页

用户在订单页输入或点击物流查询后，系统调用接口并展示快递公司、当前状态、最新节点和时间线，减少用户跳转到第三方快递网站的操作。

### 小程序查快递

小程序后端接收用户输入的快递单号，通过服务端调用接口，再把结构化轨迹返回给前端。API Key 应保存在服务端，避免暴露在小程序代码包中。

### 客服和售后系统

客服人员可以在工单页面直接查看物流节点。结合 `operateMessage` 和 `operateTime`，可以快速判断包裹是否揽收、运输中、派送中或已经签收。

### 聚合物流查询工具

对于需要支持不同快递公司的工具类网站，使用自动识别接口可以减少逐家公司对接的工作量，统一查询入口和返回格式。

## 积分不足或查询失败怎么办？

常见错误包括：

- `11001`：未提供调用密钥；
- `11002`：密钥错误；
- `11004`：积分余额不足；
- `11005`：请求过于频繁；
- `11011`：收费接口需要有效密钥；
- `11018`：请求方式不允许；
- `11023`：密钥已过期；
- 返回 `code` 非 `0000000000`：本次业务查询未成功。

出现积分不足时，请登录 Tmini 控制台补充积分或调整令牌额度。对于网络超时、临时服务异常等情况，可以采用指数退避重试，但不要连续高频请求同一个单号。

## 快递查询接口的计费和缓存建议

当前接口为 **4 积分/次**。物流轨迹通常不会每秒变化，因此没有必要在用户刷新页面时每次都重新扣积分。建议在业务侧按单号缓存结果，例如运输中的订单每隔几分钟刷新一次，已签收订单延长缓存时间。

缓存时可以保存查询时间、当前状态、最新节点和完整轨迹。下一次请求先判断缓存是否过期，再决定是否调用 API。这样既能减少积分消耗，也能降低接口压力。

## 接入时的安全注意事项

API Key 只能放在后端环境变量或密钥管理系统中，不要写入前端 JavaScript、浏览器地址栏截图、公开仓库或日志。请求建议使用 HTTPS，避免密钥和快递单号在传输过程中泄露。

另外，物流轨迹属于订单相关信息，应用应根据业务需要控制展示范围，避免在公开页面暴露不必要的收件人、地址或取件信息。

## 常见问题 FAQ

### 快递查询 API 支持哪些快递公司？

接口会根据快递单号自动识别承运公司，并返回 `cp` 和 `cpName`。具体识别结果以接口当次返回为准，建议不要在业务中写死一个固定快递公司列表。

### 查询刚发出的单号没有轨迹怎么办？

刚寄出或快递公司尚未回传数据时，`trackingDetails` 可能为空。这种情况不一定是接口异常，建议间隔一段时间后再查，并做好空轨迹页面提示。

### 接口返回的时间是什么格式？

`operateTime` 和轨迹中的 `time` 通常为 `yyyyMMddHHmmss`，例如 `20260627121900`。前端展示时可以转换为 `2026-06-27 12:19:00`。

### 可以在前端直接调用快递查询 API 吗？

不建议。直接调用会暴露 Key，可能导致积分被盗用。推荐由自己的后端服务调用 Tmini，再由后端向网页或小程序返回必要的物流字段。

### 物流接口一次可以查询多个单号吗？

当前接口参数 `trackingNo` 为单个快递单号，建议一次请求查询一个单号。批量场景可以在后端队列中限速调用，并结合缓存控制成本。
